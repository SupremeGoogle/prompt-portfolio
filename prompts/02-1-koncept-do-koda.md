# Мини-игра, которую каждый день дописывает роутина Claude

**Кейс 2 · шаг 1 — Концепт до кода**

> Мой собственный проект, не клиентский. Мобильная викторина-сравнение: две карточки и вопрос — кто тяжелее, кто быстрее, кто дольше спит, что выше. Верный ответ +1, ошибка −2, серия верных даёт множитель. Тридцать уровней, у каждого своя тема и свои двадцать с лишним карточек с фактами.

- **Код:** [github.com/SupremeGoogle/GuessWhat](https://github.com/SupremeGoogle/GuessWhat) — бэклог, история агента и оператор лежат прямо в репозитории
- **Стек:** React 18 + TypeScript strict, Vite 6, чистый CSS на переменных, lucide-react, Web Audio API, canvas-confetti
- **Инструмент:** Claude, ежедневная роутина

## Зачем такой промт

Первый промт ничего не кодит. Задача — получить три разные механики и выбрать одну по критерию масштабируемости контента, а не чинить потом ту, что модель придумала между делом.

## Промт

```text
<role>
Ты продуктовый дизайнер мобильных казуальных игр. Ты много раз
видел, как хорошая механика умирает от того, что контент
в неё невозможно добавлять.
</role>

<task>
Придумать механику для веб-викторины, которую человек открывает
с телефона и играет 2–3 минуты, без регистрации, без обучения
и без объяснений.
</task>

<context>
Аудитория: подростки 10–16 лет и их родители. Заход только
по прямой ссылке, никаких сторов и установок. Контент делаю я
сам по вечерам, поэтому добавление новой темы должно стоить мне
один файл и ноль правок в коде — иначе игра остановится
на третьем уровне.
</context>

<deliverable>
Три концепта. По каждому строго по этой сетке:
1. Механика в одном предложении.
2. Что игрок делает в первые 5 секунд.
3. Почему он откроет игру второй раз.
4. Как устроены данные, чтобы новая тема была одним новым файлом.
5. Слабое место концепта — честно, а не для галочки.
   Если слабых мест не назвал, значит не думал.
</deliverable>

<constraints>
Ничего не кодируй, не предлагай стек и не рисуй интерфейс.
Только концепты, таблицей.
</constraints>
```

## Что выдала модель

Три механики: сравнение двух объектов, угадывание по нарастающим подсказкам и «правда или миф». Первая выиграла по четвёртому пункту — данные ложатся в плоский массив, новая тема действительно один файл. У второй честно назван недостаток: подсказки нужно писать вручную под каждый объект, это в разы дороже по контенту.

## Что доработал руками

Модель предложила +1 за верный ответ и 0 за неверный. При такой экономике выгодно тыкать наугад, риска нет. Поставил −2 за ошибку. Позже добавился множитель за серию с шагом 3, и пороги звёзд пришлось пересчитать с 4/8 на 10/20 — старые брались слишком легко.
