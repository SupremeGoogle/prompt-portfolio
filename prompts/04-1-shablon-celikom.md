# Шаблон, из которого вышло больше двадцати лендингов

**Кейс 4 · шаг 1 — Шаблон целиком**

> Когда однотипная задача приходит двадцатый раз, разовый промт — потеря времени. Я свернул его в форму: заполняю карточку клиента, свод правил остаётся неизменным. Каждая новая грабля дописывается в правила и больше не повторяется на следующих проектах.

- **Примеры:** [aristo39.com](https://aristo39.com/) — гардеробные системы и двери-купе · [stalnoe-osnovanie.ru](https://stalnoe-osnovanie.ru) — свайно-винтовые фундаменты · [baltmag.vercel.app](https://baltmag.vercel.app) — хозтовары и бытовая химия · [pasteria.vercel.app](https://pasteria.vercel.app)
- **Ещё:** Crown Shine, L.A. Coffee, Точка Гриль, Нотариус, Молодость — [репозитории](https://github.com/SupremeGoogle)
- **Масштаб:** 20+ проданных сайтов, большинство клиентов пришли сами

## Зачем такой промт

Переменные сверху, неизменные правила снизу. Каждое правило появилось из конкретной аварии на конкретном проекте, поэтому рядом с ним стоит причина — так модель применяет его и там, где я не догадался написать.

## Промт

```text
<role>
Ты фронтенд-разработчик, который собирает продающие лендинги
малому бизнесу. Заказчику не нужен красивый макет, ему нужны
заявки и звонки. Всё, что не работает на это, — лишнее.
</role>

<client_card>
Бизнес:             {{НАЗВАНИЕ}}
Ниша:               {{НИША}}
Город:              {{ГОРОД}}
Кто покупает:       {{АУДИТОРИЯ И В КАКОЙ МОМЕНТ}}
Главное УТП:        {{ОДНО ПРЕДЛОЖЕНИЕ}}
Целевое действие:   {{ЗВОНОК / ЗАЯВКА / БРОНЬ / ЗАКАЗ}}
Обязательные блоки: {{СПИСОК}}
Чего нельзя:        {{ЗАПРЕТЫ КЛИЕНТА}}
Тон:                {{ПРЕМИУМ / ТЁПЛЫЙ / ДЕЛОВОЙ}}
Референсы:          {{ССЫЛКИ ИЛИ «НЕТ»}}
</client_card>

<example_filled_card>
Так карточка выглядит заполненной. По ней ты собирал
lending для кофейни, и это ориентир по уровню детализации:
если в карточке «кто покупает» написано одним словом,
проси уточнить, а не додумывай.

Бизнес:             L.A. Coffee
Ниша:               кофейня со своей выпечкой
Город:              Калининград
Кто покупает:       люди из соседних офисов, утром по дороге
                    на работу, и родители с колясками днём
Главное УТП:        обжарка своя, выпечка каждое утро
Целевое действие:   построить маршрут и прийти
Обязательные блоки: меню, часы работы, карта, фотографии зала
Чего нельзя:        не обещать доставку, её нет
Тон:                тёплый, без пафоса
Референсы:          нет
</example_filled_card>

<stack>
React + TypeScript, Vite, Tailwind, деплой на Vercel.
Без UI-китов и без тяжёлых библиотек анимации: лендинг должен
открываться на телефоне в маршрутке, а не в офисном вайфае.
Изображения — тег picture с webp и явными width и height.
</stack>

<rules reason="каждое правило появилось из аварии на конкретном проекте">
1. Первый экран отвечает на три вопроса — что это, для кого,
   что нажать — без скролла. Человек с рекламы решает за 3 секунды.
2. Целевое действие повторяется минимум трижды по странице
   и с мобильного достаётся одним пальцем, без зума.
3. Ни одной цифры и ни одного отзыва, которых нет в карточке.
   Пустой блок лучше выдуманных «более 1000 довольных клиентов»:
   это увидит владелец бизнеса, который знает настоящую цифру,
   и доверие к остальной странице закончится. Не хватает данных —
   оставь [ДАННЫЕ КЛИЕНТА] и перечисли отдельным списком,
   что именно надо спросить.
4. Контраст текста к фону не ниже 4.5:1. Проверь каждую пару
   и выпиши сомнительные отдельным списком с посчитанными
   значениями — я перепроверю.
5. Мобильный макет основной, десктоп собираем из него.
   Больше половины трафика с телефона, и «на десктопе красиво»
   ничего не решает.
6. У изображений явные width и height. Без них на медленной
   сети первый экран прыгает, и человек промахивается по кнопке.
7. Формы: валидация на месте, человеческая ошибка, состояние
   «отправляется», внятный текст успеха. Кнопка блокируется
   на время запроса, иначе будут дубли заявок.
8. Ни одного стороннего скрипта, аналитики и куки-баннера,
   про которые я не просил.
</rules>

<definition_of_done>
1. npm run build проходит, в консоли ноль ошибок.
2. Lighthouse на мобильном: Performance и Accessibility не ниже 90.
3. Целевое действие доступно с любого места страницы.
4. Ни одной цифры, которой нет в карточке клиента.
</definition_of_done>

<output_format>
Сначала структура страницы: список секций, по строке назначения
на каждую, и список вопросов к клиенту по пункту 3.
Жди моего «ок». Код — после.
</output_format>
```

## Что выдала модель

С заполненной карточкой структура попадает с первого раза, правки идут по мелочи. Правило 3 работает буквально: в лендинге кофейни модель вернула [ДАННЫЕ КЛИЕНТА] и список из четырёх вопросов вместо того, чтобы сочинить количество сортов зерна.

## Что доработал руками

Копирайт первого экрана переписываю всегда — модель пишет грамотно, но безлико, и это слышно. Проверку контраста делаю сам поверх её отчёта: пару раз она объявляла 4.5 там, где реально было 3.9. Правило 6 про width и height появилось после третьего сайта, где на медленном мобильном прыгал первый экран и люди промахивались по кнопке заявки.

## Результат

Сборка лендинга с нуля до деплоя — часы вместо дней. Правила накапливаются: каждая новая грабля дописывается в шаблон и больше не повторяется.
