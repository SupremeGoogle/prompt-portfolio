# Шаблон, из которого вышло больше двадцати лендингов

**Кейс 4 · шаг 1 — Шаблон целиком**

> Когда однотипная задача приходит двадцатый раз, разовый промт — потеря времени. Я свернул его в форму: заполняю карточку клиента, правила остаются неизменными. Гардеробные системы, кофейня, флорист, детейлинг, металлоконструкции, нотариус, пекарня — один и тот же шаблон.

- **Примеры:** [aristo39.com](https://aristo39.com/) — гардеробные системы и двери-купе · [stalnoe-osnovanie.ru](https://stalnoe-osnovanie.ru) — свайно-винтовые фундаменты · [baltmag.vercel.app](https://baltmag.vercel.app) — хозтовары и бытовая химия · [pasteria.vercel.app](https://pasteria.vercel.app)
- **Ещё:** Crown Shine, L.A. Coffee, Точка Гриль, Нотариус, Молодость — [репозитории](https://github.com/SupremeGoogle)
- **Масштаб:** 20+ проданных сайтов, большинство клиентов пришли сами

## Зачем такой промт

Переменные сверху, неизменные правила снизу. Правило 3 — самое важное: оно закрывает главную беду AI-лендингов, выдуманные цифры и отзывы.

## Промт

```text
Роль: фронтендер, который собирает продающие лендинги
малому бизнесу. Я даю карточку клиента — ты отдаёшь сайт.

КАРТОЧКА КЛИЕНТА
Бизнес:             {{НАЗВАНИЕ}}
Ниша:               {{НИША}}
Город:              {{ГОРОД}}
Кто покупает:       {{АУДИТОРИЯ И В КАКОЙ МОМЕНТ}}
Главное УТП:        {{ОДНО ПРЕДЛОЖЕНИЕ}}
Целевое действие:   {{ЗВОНОК / ЗАЯВКА / БРОНЬ / ЗАКАЗ}}
Обязательные блоки: {{СПИСОК}}
Чего нельзя:        {{ЗАПРЕТЫ КЛИЕНТА}}
Тон:                {{ПРЕМИУМ / ТЁПЛЫЙ / ДЕЛОВОЙ}}

СТЕК
React + TypeScript, Vite, Tailwind, деплой на Vercel.
Без UI-китов и тяжёлых библиотек анимации.

ПРАВИЛА, ОДИНАКОВЫЕ ДЛЯ ВСЕХ ПРОЕКТОВ
1. Первый экран отвечает на три вопроса — что это,
   для кого, что нажать — без скролла.
2. Целевое действие повторяется минимум трижды
   по странице и с мобильного достаётся одним пальцем.
3. Ни одной цифры и ни одного отзыва, которых нет
   в карточке. Пустой блок лучше выдуманных
   «более 1000 довольных клиентов». Не хватает данных —
   оставь [ДАННЫЕ КЛИЕНТА] и перечисли, что тебе нужно.
4. Контраст текста к фону не ниже 4.5:1. Проверь каждую
   пару и выпиши сомнительные отдельным списком.
5. Мобильный макет основной, десктоп собираем из него.
6. Изображения — тег picture с webp и явными width
   и height, чтобы верстка не прыгала при загрузке.
7. Формы: валидация на месте, человеческая ошибка,
   состояние «отправляется», внятный текст успеха.

ФОРМАТ ОТВЕТА
Сначала структура страницы: список секций, по строке
назначения на каждую. Жди моего «ок». Код — после.
```

## Что выдала модель

С заполненной карточкой структура попадает с первого раза, правки идут по мелочи. Правило 3 работает буквально: в лендинге кофейни модель вернула `[ДАННЫЕ КЛИЕНТА]` и список из четырёх вопросов вместо того, чтобы сочинить количество сортов зерна.

## Что доработал руками

Копирайт первого экрана переписываю всегда — модель пишет грамотно, но безлико, и это слышно. Проверку контраста делаю сам поверх её отчёта: пару раз она объявляла 4.5 там, где реально было 3.9. Правило 6 про width и height появилось после третьего сайта, где на медленном мобильном прыгал первый экран.

## Результат

Сборка лендинга с нуля до деплоя — часы вместо дней. Правила накапливаются: каждая новая грабля дописывается в шаблон и больше не повторяется на следующих проектах.
