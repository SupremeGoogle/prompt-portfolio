# Бот, который не теряет источник лида

**Кейс 6 · шаг 1 — Постановка задачи от метрики, а не от функции**

- **Боты:** [t.me/kiberoneKLD_bot](https://t.me/kiberoneKLD_bot) · [t.me/veri_x_bot](https://t.me/veri_x_bot) · [t.me/AZTmoto_bot](https://t.me/AZTmoto_bot)
- **Стек:** Python, aiogram 3 с FSM, PostgreSQL, Flask на приёме вебхуков, REST API CRM с ключом в заголовке

## Промт

```text
<role>
Ты разработчик, который делает боты для отдела продаж.
Ты знаешь, что бот, теряющий заявку, хуже отсутствия бота:
человек написал, ему не ответили, и он ушёл к конкуренту.
</role>

<goal>
Принимать поток заявок из рекламы так, чтобы в конце месяца
можно было ответить на вопрос: какой канал приносит записи,
а не клики.
</goal>

<requirements>
1. Ловить /start с параметром: t.me/bot?start=vk_march —
   всё после start это метка источника. Сохранять её в карточку
   лида сразу, до первого сообщения человека. Иначе метка
   теряется на тех, кто нажал start и ушёл думать, — а это
   как раз самая интересная для аналитики группа.
2. Короткий диалог на FSM: имя, телефон, возраст ребёнка,
   удобное время. По одному вопросу за раз, с кнопкой «назад»
   на каждом шаге. Телефон принимать и кнопкой «поделиться
   контактом», и текстом — часть людей боится кнопки.
3. Создавать сделку в CRM через вебхук и класть метку источника
   в отдельное поле, а не в комментарий: из комментария её
   потом не сгруппировать.
4. Рассылка по сегменту, а не всем подряд: фильтр по источнику,
   по статусу сделки, по факту пробного занятия.
</requirements>

<examples>
Тон и длина реплик бота. Каждая лишняя строка — это лишний
экран на телефоне.

<example type="плохо">Здравствуйте! Благодарим вас за интерес
к нашей школе программирования. Для того чтобы мы могли
подобрать для вашего ребёнка оптимальную программу обучения,
пожалуйста, укажите ваше имя.</example>
<example type="хорошо">Здравствуйте! Как вас зовут?</example>

<example type="плохо">Пожалуйста, введите корректный номер
телефона в формате +7XXXXXXXXXX.</example>
<example type="хорошо">Кажется, в номере опечатка. Пришлите ещё
раз или нажмите кнопку ниже — телефон подставится сам.</example>

<example type="хорошо">Записал. Ждём вас в субботу в 11:00,
Ленинский проспект 30. За день напомню.</example>
</examples>

<reliability>
— Ключ CRM только из переменных окружения. В коде его быть
  не должно ни в каком виде, включая значение по умолчанию.
— Вебхук CRM отвечает не мгновенно и иногда таймаутит.
  Любой запрос к нему — с ретраем и экспоненциальным бэкоффом.
  Лид не должен теряться из-за одного таймаута.
— Если CRM недоступна совсем, заявка всё равно сохраняется
  в свою базу со статусом «не доставлено», и есть команда,
  которая досылает такие заявки пачкой.
— Рассылка с паузой между отправками, чтобы не словить лимит
  Telegram, и с логом: кому ушло, кому нет и почему.
  Блокировка бота пользователем — это нормальный исход,
  а не ошибка, её надо записать и идти дальше.
</reliability>

<definition_of_done>
1. Заявка доходит до CRM при принудительно уроненном вебхуке
   (проверяется отключением сети на время запроса).
2. Метка источника видна в карточке сделки отдельным полем.
3. Рассылка на 200 человек не ловит лимит и оставляет лог.
4. Поиск по репозиторию не находит ключей и токенов.
</definition_of_done>

<output_format>
Сначала схема БД и граф состояний диалога, текстом.
Код — после моего «ок».
</output_format>
```
