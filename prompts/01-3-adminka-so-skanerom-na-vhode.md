# Городское собрание: лендинг, QR-билеты и админка на входе

**Кейс 1 · шаг 3 — Админка со сканером на входе**

- **Лендинг:** [https://kiberone.vercel.app](https://kiberone.vercel.app/)
- **Код:** [https://github.com/SupremeGoogle/KIBERone](https://github.com/SupremeGoogle/KIBERone)
- **Стек:** React 19 + TypeScript, Vite, Tailwind, react-router-dom 7. Supabase — база и realtime, qrcode.react — генерация QR, @yudiel/react-qr-scanner — сканер, EmailJS — письма, jsPDF + html2canvas — PDF-билет, motion — анимации
- **Инструмент:** Codex

## Промт

```text
<role>
Ты делаешь внутренний инструмент для одного человека на один
вечер. Красота вторична, скорость и предсказуемость — главное.
</role>

<scenario>
Родитель подходит к столу, показывает QR с телефона или
с распечатки. Менеджер сканирует и отмечает приход. За ним
очередь, в зале шумно, телефон менеджер держит одной рукой,
вторая занята списком. Если отметка занимает больше секунды,
очередь встаёт.
</scenario>

<requirements>
1. Вход по паролю. Пароль берётся из переменной окружения,
   в коде и в репозитории его быть не должно ни в каком виде,
   включая «значение по умолчанию на случай отсутствия».
   Сессия держится в sessionStorage и умирает с вкладкой.
2. Сканер камерой через @yudiel/react-qr-scanner, тыловая
   камера по умолчанию, открывается в модальном окне.
3. Разбор кода: сначала пробуй прочитать как идентификатор,
   затем как ссылку с параметром. Не нашёл в базе — покажи
   «Билет не найден» с самим значением, чтобы менеджер мог
   продиктовать его мне.
4. После скана — крупная карточка: имя, сколько человек и
   один из трёх статусов:
   • зелёный «Пришёл»;
   • жёлтый «Уже отмечен» с временем первой отметки — это не
     ошибка, а обычная ситуация, когда семья идёт по одному билету;
   • красный «Билет не найден».
   Статус читается с расстояния вытянутой руки по цвету,
   не читая текст.
5. Список всех регистраций: поиск по имени родителя, имени
   ребёнка, телефону и почте; сортировка по дате и по имени.
   Сортировка по имени — с учётом кириллицы, иначе «Ёлкина»
   уедет в конец списка.
6. Счётчики сверху: всего зарегистрировано, с билетом,
   в листе ожидания, пришло.
7. Выгрузка отфильтрованного списка в CSV. Файл открывают
   в Excel, поэтому нужен BOM, иначе кириллица превратится
   в кракозябры.
8. Новые регистрации появляются в списке сами, через
   realtime-подписку Supabase, без перезагрузки страницы.
</requirements>

<constraints>
— Вёрстка под телефон в руке: кнопки крупные, попадание пальцем
  без прицеливания, минимальная зона нажатия 48×48 px.
— Отметка проходит меньше чем за секунду: сначала показывай
  результат в интерфейсе, потом досылай запрос.
— Связь в зале проседает. Неудачная отметка встаёт в очередь
  и повторяется, а не теряется молча.
— Ошибочную отметку можно снять тут же, одной кнопкой.
— Удаление регистрации — только с подтверждением и только
  вручную из списка. Никаких массовых операций: случайное
  нажатие не должно стоить кому-то места в зале.
— Не добавляй роли, права и приглашения администраторов.
  Пользователь ровно один, всё остальное — лишний код.
</constraints>

<examples>
Формулировки на карточке после скана. Менеджер читает их
в шуме и за полсекунды, поэтому важна каждая.

<example type="плохо">Статус: CHECKED_IN</example>
<example type="хорошо">Пришёл · 2 человека</example>

<example type="плохо">Ошибка: дубликат отметки</example>
<example type="хорошо">Уже отмечен в 18:42 · 2 человека —
это нормально, если семья идёт по одному билету</example>

<example type="плохо">Not found</example>
<example type="хорошо">Билет не найден · 7f3a91 — продиктуйте
этот код администратору</example>
</examples>

<tooling>
Правки вноси через apply_patch, файлы читай пакетом, а не по
одному. Команды оболочки — только там, где инструмента нет.
</tooling>

<definition_of_done>
1. Скан того же билета дважды подряд даёт жёлтый статус,
   а не две отметки.
2. При выключенной сети отметка не теряется и уходит
   после восстановления связи.
3. CSV открывается в Excel с правильной кириллицей.
4. Пароля нет ни в одном файле репозитория (проверь поиском).
</definition_of_done>
```
